# Accessibility audit, WCAG 2.2 AA (S-227) — 2026-11-13

Owner: launchprep job (accessibility-specialist, test-engineer roles). Build: main at 90cee6e plus
this change. Tools: axe-core 4.11 through Playwright (`tests/e2e/a11y-audit.spec.ts`, tags wcag2a,

## Findings

Zoom is emulated as the browser does it (the CSS viewport halves), so 200% on a 320 px phone is
160 CSS px wide: stricter than WCAG 1.4.10, which asks for reflow at 320 CSS px. Severity reflects that.

| ID | WCAG | Severity | Where | What | Owner | State |
|---|---|---|---|---|---|---|
| A11Y-01 | 1.4.10 Reflow | S3 | Admin new/edit product, 320 and 375 px at 200% | Every section 192 px wide: the form is a one-column grid whose implicit `auto` track grows to its widest content | frontend | **Fixed**: explicit `minmax(0,1fr)` track (`routes/admin/product.tsx`) |
| A11Y-02 | 1.4.10 | S3 | Admin new promotion, 320 and 375 px at 200% | Start/End date-time fields 229 px wide (same grid cause) | frontend | **Fixed** (`routes/admin/promotion.tsx`) |
| A11Y-03 | 1.4.10 | S4 | Admin product editor while options load | The options skeleton bar is a fixed 192 px | frontend | **Fixed**: `max-w-full` |
| A11Y-04 | 1.4.10 | S3 | Admin Promotions list, 320 px at 200% | "New promotion" button 7 px wider than the screen | frontend + ux | **Fixed**: below 12rem of CSS width the button tightens (gap, padding, text size); normal widths unchanged |
| A11Y-05 | 1.4.10 | S3 | French tracking page, 320 and 375 px at 200% | The heading "Avancement" plus its decorative gold rule (fixed 24 px minimum) did not fit, 2 px sideways scroll | design | **Fixed**: the rule may shrink to nothing (`section-title-start` in `app.css`) |
| A11Y-06 | 1.4.10 | S3 | French `/fr/account` and `/fr/account/orders`, 320 px at 200% | 23-24 px too wide: "Enregistrer" and "Commander" buttons and the "Mes commandes" heading row do not wrap | E-11 (accounts) | **Open**. Recorded in the spec as a scoped, annotated exception; axe still runs there |

Not accessibility, recorded for the performance report: Lighthouse lab runs report CLS 0.567 on
`/basket` from the footer although the filmstrip shows no visible movement; a real Chrome measurement
gives CLS ≤ 0.076 (`production/audits/perf-checkout-2026.md`).
